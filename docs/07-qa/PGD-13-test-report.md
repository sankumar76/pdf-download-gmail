**Observations (not defects unless listed in the next section).**
- **Closed pipes.** With the parent's read end of the stdout pipe closed, `--help` exits **120**; with a closed stderr pipe and an unexpected failure, the process exits **120** instead of 1 (`main` returned 1; the interpreter's flush of the unsent line at shutdown fails). The base `1ce8473` and a plain `python -c "print('x')"` give 120 for stdout too, so it is not new, but PGD-13's unraisable hook now hides the "Exception ignored" line, so the exit is silent. DEF-006.
- **Library warnings are invisible by default.** `logging.captureWarnings(True)` hands `warnings.warn` text to the `py.warnings` logger, which gets a `NullHandler`, so with no handler configured nothing reaches stderr (child run: stderr empty). That is safe, and it is by design, but it also hides non-secret warnings (for example a library's end-of-support notice) until the log handler of STORY-07.02 exists. Note for that story.
- **Console encoding (test plan OQ-5, R-05).** `PYTHONUTF8` unset on a Windows pipe gives `cp1252` for stdout and stderr (stderr uses `backslashreplace`, stdout is strict). The story's own stderr lines are ASCII and unaffected, and a non-ASCII secret did not change the fixed lines or the exit code. But with `PYTHONUTF8` unset, `print(safe_message(GmailPdfError("... ✓ 日本")))` to stdout raises `UnicodeEncodeError`, and a `StreamHandler(sys.stdout)` logging the same text prints a `--- Logging error ---` block with a traceback (the message in it is redacted; no secret). With `PYTHONUTF8=1` both work, which is the CI behaviour that masks the problem. The decision OQ-5 asks for is still needed before the first story that prints names.
- **Registry and whitespace.** `register_secret("abcdefgh\n")` and `register_secret(" abcdefgh ")` register the padded text only; the bare `abcdefgh` is then not redacted. The AC says "exact occurrence of the value", so this is within it, but a token read from a file with a trailing newline would be only half protected (the `ya29.`/`1//`/`GOCSPX-` shapes still match). Recommend the auth stories (STORY-01.04) strip before registering, or the function strip. Not logged as a defect: no AC or documented behaviour is contradicted, and no production code registers a secret yet.
- **Extra pattern gaps (class tracked in #24).** Escaped-JSON and quoted-value-with-space forms, listed in AC-2 above. `register_secret("REDACTED")` makes `redact` non-idempotent (`[[REDACTED]]`); contrived.
- **Worker thread failure and exit status (R-12).** An exception in a worker thread prints the fixed line but the process still exits 0 if the main thread finishes. In the skeleton there are no workers; the runner stories must propagate a worker failure to exit 1 (test plan section 9 item 4).
- Absent streams: `sys.stderr = None` with a failure exits 1 silently; `sys.stdout = None` sends help to stderr (argparse's behaviour). No crash.

## Known Limits (recorded, not defects)

1. **Accepted residual (P10, E1, E11; #29).** A real interrupt delivered outside the hook's guarded body (at hook entry, before the `try`, or at hook exit) can still make CPython print the original exception unredacted. No `except` clause can close it; STORY-06.02 closes it on the CLI by setting a flag from SIGINT. I did not try to reproduce it, as instructed.
2. **Exit `0xC000013A` on Windows for an interrupt inside `main`'s `except Exception` block (P3, P4; AC-8; #29).** I reproduced the shape in a real child with a genuine console Ctrl+C delivered while `main` was reporting an unexpected failure (`python -m gmail_pdf` and `gmail-pdf.exe`, same result). **What a user sees:** two lines on stderr, `error: unexpected failure, see the run log` and then `Run cancelled`; no traceback, no secret; the process status is `3221225786` (hex `C000013A`, STATUS_CONTROL_C_EXIT; `-1073741510` in `%ERRORLEVEL%` of `cmd`), not 1. Needs a failure and a second Ctrl+C inside a window of milliseconds. AC-8's normal case (Ctrl+C during the run) gives exit 1, as shown above.
3. Argparse usage errors are not redacted (#23); `SystemExit(text)` (QUA-37, #23); #24, #27, #28 and QUA-34..36 are open and not logged again. The three Sev-4 test-support defects from earlier stories (DEF-001..004) are untouched.
